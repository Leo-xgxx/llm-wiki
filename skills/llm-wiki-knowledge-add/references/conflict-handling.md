# 冲突知识处理规范（conflict-handling）

写入任何知识前，必须先运行 `scripts/check_conflicts.py` 检索候选冲突条目，再按本规范判定与处理。

## 判定矩阵

| 场景 | 判定标准 | 处理动作 |
|---|---|---|
| 纯新增 | 无命中，或命中条目与新知识主题不同 | 正常新建条目 |
| 补充 | 新知识是既有条目的扩展/细化，结论不矛盾 | 更新既有条目，**不新建文件**；刷新 `updated`；变更记录追加一行 |
| 矛盾 | 新知识与既有条目结论相反 | 见下方"矛盾处理流程" |
| 过期 | 既有条目描述的事实已失效（如表下线、口径废弃） | 既有条目 `status: deprecated` + 正文顶部标注替代链接；新建替代条目；两个索引同步更新 |

## 矛盾处理流程

1. 比较双方的 `source` 与 `updated`：
   - 一方有权威来源（工具查询/官方文档）而另一方是口述 → 以权威来源为准；
   - 来源同级 → 以时间较新的一方为准。
2. 仍无法判断 → **必须向用户确认**，展示两个结论及各自来源，由用户裁决。禁止擅自覆盖。
3. 确认后更新条目，变更记录必须包含：旧结论、新结论、变更原因、日期。

### 示例

既有条目：`concepts/dau-definition.md` — "DAU 统计口径包含游客"。
用户新消息："DAU 从这个月开始不算游客了。"

处理：命中冲突 → 属于**矛盾**且用户消息更新 → 更新该条目定义，`updated` 刷新，变更记录追加：

```markdown
| 2026-07-04 | DAU 口径由"含游客"改为"不含游客" | 用户告知口径变更 |
```

## 铁律

- 永远**不物理删除**历史条目文件；废弃用 `deprecated` 标记。
- 任何冲突处理后必须重跑 `validate_wiki.py` 确认索引一致。
- 同一知识只允许一个 active 条目；发现重复条目时合并为一个，另一个标记 deprecated 并指向合并后的条目。
